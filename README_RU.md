# DiagPDF — Генератор шахматных диаграмм

Конвертирует файлы PGN / FEN / EPD в страницы с шахматными диаграммами —
**PDF, LaTeX, HTML, EPUB, DOCX, RTF или Markdown**.

Что изменилось в каждой версии — в [CHANGELOG.md](CHANGELOG.md); что запланировано —
в [ROADMAP.md](ROADMAP.md) и [SPEC.md](SPEC.md). Основная документация ведётся
на английском в [README.md](README.md); этот файл — её сокращённый русский вариант.

## Скачать

Последнюю версию **DiagPDF.exe** можно получить в разделе [Releases](../../releases) — Python не нужен.

## Возможности

- Чтение файлов `.pgn`, `.fen`, `.epd` (UTF-8 или cp1252, кодировка определяется автоматически)
- **Диаграммы из ходов партии** — обычный PGN подходит как есть, тег `[FEN]` не обязателен
- Запись `.pdf`, `.tex`, `.html`, `.epub`, `.docx`, `.rtf`, `.md`
- 7 макетов страницы: 1–4 колонки, до 20 диаграмм на страницу
- 17 шрифтов доски в комплекте плюс `AlphaDG`, который собирает
  `build_alphadg.py` — точный список вашей копии покажет `--list-fonts`
- **Положите шрифт в `Fonts/` — программа его подхватит**, определив раскладку фигур
  по глифам, которые в нём действительно есть, а не по имени файла
- Индикатор хода: квадрат □■, круг ○●, треугольник △▲
- Авто-переворот доски при ходе чёрных
- Координаты доски (опционально)
- Гибкие подписи диаграмм через шаблон: `{number}`, `{event}`, `{white}`, `{black}`, `{date}`, `{comment}`
- Нотационные линии под диаграммами: пустые или пронумерованные (1–5 строк)
- **Диапазон позиций**: сгенерировать только позиции N–M (`--from` / `--to`)
- **Раздел ответов** с фигурными обозначениями, 1 или 2 колонки, при желании
  напечатанный вверх ногами, чтобы решение не попалось на глаза случайно;
  в конце книги или после каждой главы (`--answers-after-chapter`)
- **Водяной знак** по диагонали на каждой странице (`--watermark`)
- **Отдельный файл-картинка на диаграмму**: PNG или SVG — последний несёт сами
  контуры глифов, поэтому масштабируется без потерь и не требует шахматного
  шрифта на другой стороне (`--export-images`)
- **Кликабельные ссылки**: заголовок диаграммы → ответ, номер ответа → диаграмма
- **Ссылки на анализ Lichess** отдельной подписью под доской, переведённой
  на язык интерфейса (`--lichess-label` — своя формулировка)
- Верхний / нижний колонтитул с переменными `{page}`, `{total}`, `{chapter}`
- Поддержка глав через тег `[Chapter "..."]` в PGN
- **Сохранённые наборы настроек** — профили, общие для CLI и окна (`--profile`)
- Титульный лист и содержание (`--cover`, `--contents`)
- Формат бумаги, ориентация и поля (`--page-size`, `--landscape`, `--margin-*`)
- Кириллица и Unicode в заголовках (через системные шрифты)
- GUI (Windows, Tkinter) + полноценный CLI
- Интерфейс на английском, русском, португальском и испанском
- Проверка FEN с отчётом по каждой позиции (`--on-invalid`)

## Установка

### Вариант A — Исполняемый файл (Windows, Python не нужен)

1. Скачайте `DiagPDF.exe` из раздела [Releases](../../releases)
2. Положите в любую папку и запустите

### Вариант B — Из исходного кода

```bash
pip install -r requirements.txt
python fen2rtf.py --gui
```

Два пакета из `requirements.txt` не обязательны, и файл помечает какие: `chess` —
для диаграмм из ходов партии (`--at-move`, `--every`, `--at-comment`), `sv-ttk` —
для темы Sun Valley в окне. Без них остальное работает: опции ходов сообщат, что
установить, а GUI перейдёт на тему, которую оформляет сам.

## Справочник CLI

```bash
python fen2rtf.py input.pgn [опции]
```

Формат вывода определяется расширением `-o`: `.pdf`, `.tex`, `.html`, `.epub`,
`.docx`, `.rtf`, `.md`.

| `-l, --layout N` | `2` | Пресет макета 0–6 (`--list-layouts` — список) |
| `-f, --font NAME` | `ChessMerida` | Шрифт доски (`--list-fonts` — список) |
| `--font-size N` | `0` | Размер шрифта доски в пт (0 = авто) |
| `--text-size N` | `0` | Размер заголовков и текста в пт (0 = пропорционально макету) |
| `--no-coords` | — | Скрыть координаты доски |
| `--flip` | — | Перевернуть доску (чёрные внизу) |
| `--no-auto-flip` | — | Отключить авто-переворот при ходе чёрных |
| `--symbol NAME` | `square` | `square` / `circle` / `triangle` |

| `--lines N` | `0` | Нотационных линий на диаграмму (0–5) |

| `--allow-restricted-fonts` | — | Встраивать шрифты, лицензия которых это запрещает |
| `--list-fonts`, `--list-layouts`, `--list-languages` | — | Показать список и выйти |
| `-v, --verbose` / `-q, --quiet` | — | Диагностика библиотек / подавить предупреждения |
| `--version` | — | Вывести версию и выйти |

Пробелы в таблице — свойства самих форматов, а не недоделки:

- **EPUB перетекает по экрану.** Разбивает на страницы программа чтения, поэтому
  своих страниц у документа нет — и колонтитулу не на чем повторяться.
- **Браузер не умеет нумеровать печатные страницы из разметки.** Счётчики страниц
  живут в полях CSS paged-media, которые браузеры не реализуют. Колонтитулы в HTML
  выводятся и повторяются на каждом печатном листе, но `{page}` и `{total}` отбрасываются.
- **Водяному знаку нужна страница.** PDF рисует его поверх каждой; в LaTeX этим
  занимается `draftwatermark`; HTML ставит фиксированный блок. Word и RTF получают
  фигуру WordArt, закреплённую в колонтитуле — единственной части этих форматов,
  которая повторяется на каждой странице. EPUB штамповать нечего.
- **Перевёрнутым ответам нужна страница, которую можно повернуть.** Весь блок
  ответов поворачивается на 180° целиком. Word умеет поворачивать текст только
  внутри фигуры, в RTF повёрнутого текста нет вовсе, а в LaTeX повёрнутый блок
  не разрывается между страницами.
- **Markdown — это поток текста.** Ни страниц, ни листа, ни шрифтов. Доска в нём
  пишется юникодными фигурами — оттуда же берутся фигуры и для ответов.
- **LaTeX рисует доску из FEN** пакетом `chessboard`, поэтому шахматные шрифты
  из комплекта — и стили рамки вместе с ними — здесь ни при чём.

Всё, что формат выполнить не может, попадает в stderr, а не отбрасывается молча:

```
Warning: EPUB does not support page header/footer (--header/--footer) - the option will be ignored
```

## Советы по формату PGN

### Подписи диаграмм

DiagPDF читает данные позиции из тегов PGN и первого комментария.
Используйте шаблон заголовка, чтобы составить нужную подпись:

```
--title-template "{number}. {event} ({date})"
--title-template "{number} {comment}"
```

### Главы

Добавьте тег `[Chapter "Название главы"]` перед группой партий.
Используйте `{chapter}` в колонтитуле для отображения текущей главы:

```pgn
[Chapter "Тактика — Связка"]
[Event "1.1 Пример"]
[FEN "..."]

1. Kg7! 1-0
```

### Раздел ответов

Ходы из тела партии PGN становятся ответами.
Комментарии `{...}` и коды NAG `$1` автоматически удаляются.
Варианты в скобках `(2...Ke8 3.Rb8#)` сохраняются.

## Шрифты

Точный список вашей копии покажет `python fen2rtf.py --list-fonts`.

Шрифты доски делятся на два семейства с разными таблицами символов:

| Семейство | Шрифты | Примечания |
|---|---|---|
| Merida-совместимые | `ChessMerida` и набор `Chess *` (13 шт.) | По умолчанию; поддерживают `--border simple/double/none` |
| Раскладка Alpha | `AlphaDG`, `LeipzigDG`, `CondalDG`, `KingdomDG`, `chess-alpha` | Рисуют индикатор хода внутри рамки доски |

Шрифты фигурной нотации (раздел ответов):

| Файл | Стиль |
|------|-------|
| `ZurichFigurine.TTF` | Сбалансированный (по умолчанию) |
| `HastingsFigurine.TTF` | Классический, детальный |
| `LinaresFigurine.TTF` | Упрощённый, современный |

В шрифт фигур набираются только начальные буквы фигур `K Q R B N`; остальной
текст хода остаётся в обычном текстовом шрифте.

`ZurichFigurine.TTF` и `LinaresFigurine.TTF` восстановлены из копий, вложенных
в `fonts_6a7de6c2db0e9/chesswin.pdf`, поэтому содержат только те глифы, которые
использовал тот PDF. Этого хватает на всё, что DiagPDF требует от шрифта фигур,
но полными начертаниями они не являются: у Zurich нет ни полного алфавита, ни
строчных букв фигур. Точность извлечения проверена по извлечённому оттуда же
`HastingsFigurine`, контуры которого совпадают с исходным шрифтом из комплекта.

Шрифты со сломанной таблицей VDMX патчатся автоматически при первом запуске;
патченая копия сохраняется как `*_patch.ttf` и используется повторно.

> **`AlphaDG.ttf` собирается, а не поставляется.** После клонирования его нет ни
> в `Fonts/`, ни в репозитории — соберите один раз:
>
> ```bash
> python build_alphadg.py
> ```
>
> Ранние выпуски упоминали этот шрифт, но в комплекте его не было. Демо-PDF 2011
> года несут его внутри, и 52 из 56 нужных символов уцелели там;
> [`build_alphadg.py`](build_alphadg.py) объединяет эти подмножества,
> восстанавливает потерянную при извлечении таблицу символов и выводит
> недостающие четыре:
>
> | Символ | Что это | Откуда взят |
> |---|---|---|
> | `'` | заливка нижнего края рамки | зеркальное отражение `z` — правило точно выполняется для обеих пар углов, которые в Alpha сохранились |
> | `$` | левый край рамки | зеркальное отражение `%` по горизонтали, как это нарисовано в `LeipzigDG`, `CondalDG` и `KingdomDG` |
> | `f` `i` | треугольный индикатор хода | нарисованы: форма — общая для тех трёх шрифтов, вписана в собственные пропорции и толщину линии Alpha |
>
> Первая диаграмма `ex1` совпадает с оригиналом 2011 года пиксель в пиксель —
> это и подтверждает, что восстановленная таблица символов верна. Два
> треугольника — единственная часть шрифта, которая нарисована, а не
> восстановлена. `python build_alphadg.py --check` покажет каждый вывод
> и его проверку.

Два шрифта из комплекта (`Chess Adventurer`, `Chess Cases`) лицензированы как
невстраиваемые. DiagPDF не включает их в пакеты EPUB и DOCX и сообщает об этом;
`--allow-restricted-fonts` переопределяет это поведение.
